# NextFi — Crypto DCA Tracker

NextFi is a mobile-first DCA tracker for long-term crypto investors. Its core promise is simple: track every DCA, know your average entry, see your profit/loss, and know whether you are on pace for the month. It is delivered as a website, installable PWA, and Android APK using one Next.js product.

## Production architecture

```text
GitHub
  |
  v
Vercel Free
  |
  v
Next.js 16 on Vercel
├── Web UI
├── Installable PWA
├── Android UI loaded by Capacitor
├── Route Handlers (/api)
├── server-side auth
└── business logic
  |
  v
Supabase Free
└── PostgreSQL
```

There is no separate NestJS API, Docker host, Oracle VM, AWS EC2 instance, Caddy proxy, or second production server.

## Current stack

- **Next.js 16 + React 19** — frontend and backend
- **Vercel** — hosting and GitHub-based deployments
- **Supabase PostgreSQL** — managed database
- **Supabase CLI** — authoritative SQL migration workflow
- **Prisma** — server-only ORM/query layer; it no longer owns migrations
- **Google Identity Services + native Google Sign-In** — one Google-only auth flow across web/PWA/APK
- **pnpm + Turborepo** — workspace tooling
- **Chart.js** — portfolio/admin analytics
- **CoinGecko** — market prices
- **Mistral** — optional AI explanations
- **IndexedDB + service worker** — offline PWA behavior
- **Capacitor 8** — Android wrapper for the deployed Next.js UI and native plugin bridge

## DCA-first product scope

- DCA-first Home screen: current value, total invested, total P/L and return
- Average entry and performance by coin
- Weekly / biweekly / monthly DCA plans
- Next-DCA date and monthly contribution target
- Current-month DCA progress based on recorded BUY transactions
- Long-term contribution pace and public DCA calculator
- Complete transaction history and weighted average cost basis
- PHP / USD / USDT and other supported reporting currencies
- Offline cached portfolio and queued transactions
- Mobile-first website with installable PWA
- Downloadable Android APK generated by GitHub Actions
- Google-only customer login with HttpOnly signed session
- Separate secure control panel, landing CMS, AdSense policy, and audit log
- Advanced ledger activity remains supported without dominating the main DCA flow
- Market and AI routes remain available in code but are intentionally removed from primary customer navigation
- SEO metadata, sitemap, robots, JSON-LD, and PWA manifest

## Local setup

Requirements:

- Node.js 22+
- pnpm 10+
- Supabase account/project access

```bash
corepack enable
pnpm install
cp .env.example apps/web/.env
```

Fill in the server-only secrets in `apps/web/.env`.

Authenticate and link the CLI once:

```bash
pnpm supabase:login
pnpm supabase:link
```

Preview and apply migrations:

```bash
pnpm db:push:dry-run
pnpm db:push
```

Generate Prisma and run:

```bash
pnpm db:generate
pnpm dev
```

Open:

- App: http://localhost:3000
- API health: http://localhost:3000/api/health
- Control panel: http://localhost:3000/admin

## Web, PWA and APK

The web app and PWA run directly from Vercel. The Android APK is a Capacitor shell that loads the same deployed Next.js UI, so UI fixes ship from one frontend and all clients call the same Next.js API/Supabase backend.

Generate the Android project once on a development machine:

```bash
pnpm install
pnpm android:init
pnpm android:open
```

Build a sideloadable APK after the Android project exists:

```bash
pnpm android:sync
pnpm android:apk
```

For a no-local-Android-Studio path, run the **Android APK** GitHub Actions workflow. It publishes a rolling APK asset used by the landing page download action.

Native Google Sign-In uses the Android credential flow and sends the returned Google ID token to the existing `/api/auth/google` endpoint. Create an Android OAuth client for package `com.curibtech.nextfi` and register the signing SHA-1.

See [docs/ANDROID_CAPACITOR.md](docs/ANDROID_CAPACITOR.md).

## Creating future database changes

Do not create Prisma migrations. Use Supabase migrations:

```bash
pnpm db:new add_portfolio_feature
```

Edit the new SQL file under `supabase/migrations/`, then run:

```bash
pnpm db:push:dry-run
pnpm db:push
```

Keep `apps/web/prisma/schema.prisma` synchronized with the SQL schema because Prisma remains the server query layer.

## Security model

All portfolio and control-panel tables have PostgreSQL Row Level Security enabled. There are intentionally no browser Data API policies for these tables; browser requests go through Next.js Route Handlers and business services.

The browser never receives `DATABASE_URL`, `DIRECT_URL`, database passwords, or control-panel/session secrets.
